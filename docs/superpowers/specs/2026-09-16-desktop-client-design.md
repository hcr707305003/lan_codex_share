# LAN Codex Share 桌面客户端设计

日期：2026-09-16

状态：布局与本设计均已确认，Windows 本地首版已实现并完成打包启动检查。未连接真实隧道、未发布版本；macOS/Linux 构建与验证流程已接入，尚未在本机执行。

## 1. 目标与边界

提供独立可视化客户端，集中管理本机 Codex Share、frpc 与 cloudflared：启动、停止、查看日志、编辑配置、定位程序，以及下载缺少的 frpc。

- 保留原有 `lan_codex_share` 默认 Share 入口、`share` / `cli` 子命令和 `--config` 行为。
- Share 仍监听一个业务端口，示例为 9000；FRP 与 Cloudflare 可以单独使用、同时使用或都不使用。
- 桌面控制功能不加入现有 Web 服务，不通过 9000 端口对外提供进程、配置或安装管理接口。
- 不管理 PHP、Webman、前后端开发服务器，也不停止外部已经运行的 frpc、cloudflared 或 Codex 客户端。
- 不替用户登录 Codex、创建 Cloudflare Tunnel、配置 DNS 或修改 frps。
- 首版不做托盘驻留、系统服务安装、开机启动和静默自动升级。

## 2. 技术路线与替代方案

推荐 Python + PySide6 / Qt Widgets，新增独立 GUI 入口，沿用现有 Python 服务与 PyInstaller 打包链路。界面按已确认的草图实现原生控件，不在桌面内加载公网网页。

比较：

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| PySide6 / Qt Widgets | 原生窗口、文件选择器与进程管理；不需要系统 WebView | GUI 包体积增加，须携带 Qt 运行库及许可证 | 推荐 |
| pywebview | 可以复用草图 HTML/CSS | 依赖各平台 WebView，需另外维护本地网页与 Python 调用边界 | 不作为首版 |
| Tkinter | 依赖较少 | 实现已确认的布局、样式和高密度日志体验需要较多额外工作 | 不作为首版 |

本次已检查 PySide6 6.11.2 的官方 PyPI wheel 列表，覆盖 Windows x64、macOS universal2、Linux x64 / ARM64。该版本 wheel 的 macOS 最低标记为 13.0，Linux x64 为 manylinux 2.34，ARM64 为 manylinux 2.39。这些是选型约束，不代表应用已经通过平台验证。

参考：[PySide6 官方包](https://pypi.org/project/PySide6/6.11.2/)。实施时固定依赖版本并验证完整依赖链；不降低现有无 GUI 入口的兼容范围。

GUI 依赖单独安装和打包；仅使用现有 CLI/Share 的用户不要求安装 Qt。

## 3. 窗口与交互

沿用确认的深色布局：左侧导航，顶部标题，底部状态栏。主内容区域独立滚动，不推走导航与顶部。

### 服务总览

三张独立服务卡：Codex Share、frpc、Cloudflare。展示当前状态、配置路径、程序位置及相应启停按钮。

- 状态：未安装、已停止、启动中、进程运行中、停止中、启动失败。
- 隧道进程运行不等于公网可达；只有确实获得连接成功证据才展示“已连接”，不根据 PID 或配置地址推断。
- Share 的“就绪”由受控子进程在成功监听后发送状态事件；端口冲突、鉴权或配置错误显示原因。
- 已运行服务不允许重复启动。停止只作用于该卡对应的受控进程，不联动停止其他卡。
- Share 停止时明确提醒隧道入口的业务服务将不可用，隧道进程仍可保留。
- 展示本地与已配置的两个公网入口，允许复制或打开；无配置的不显示虚构地址。

### 配置管理

按文件区分 Share、frpc、Cloudflare，允许选择现有文件和从安全示例创建文件。

- Share：基础表单包括工作目录、端口、Session、权限、密码、预览目录及两个公网入口；高级字段通过原始 TOML 编辑。
- 保留 `session_ids` 缺省、空数组和指定数组三种现有语义，不把缺省自动变为空数组。
- frpc：基础表单包括服务器地址/控制端口、认证 token、TLS、选定 TCP 代理的本地地址/端口和公网端口；保留其他代理及未知字段。
- 多代理文件不强行改写为单代理；用户先选择要编辑的 TCP 代理，其他内容不动。
- Cloudflare：首版编辑已有本地 YAML 配置并选择凭证文件；另支持远程管理 Tunnel 的 token 文件启动模式。token 模式与本地 YAML 模式二选一，不将 token 放进命令行参数。
- 表单和原始配置共享同一文档模型。原始内容解析失败时禁止保存和切回表单，保留编辑内容并定位错误。
- 密码/token 表单默认掩码，未编辑的密钥原值不被掩码字符串覆盖。原始配置模式明确提示可能显示敏感内容。
- 保存只写文件，不自动重启；运行实例继续使用旧配置，卡片显示“配置已变更，重启后生效”。

### 组件管理

- 显示组件是否存在、来源、版本、路径及检测错误。
- frpc 支持选择本地程序、官方发行版下载和打开官方下载页。
- cloudflared 首版支持选择已有程序和打开官方下载页，不额外实现第二套自动安装器。
- Codex CLI 沿用项目现有的外部命令检测；现有 `cli` 子命令是会话接入入口，不将其误认为已内置上游 Codex 二进制。
- 下载完成不自动启动隧道；下载失败不改变现有程序。

### 运行日志

按服务筛选、搜索、暂停显示、恢复显示、清空当前显示和导出。暂停显示不暂停服务或日志采集。

保留至多 10,000 条显示记录，单条至多 16 KiB；使用批量刷新，禁止每行追加触发整页重绘。桌面日志轮转为每份 5 MiB、最多 3 份。超限明确显示丢弃计数。

导出仅导出当前筛选结果。进入缓存和文件之前先遮蔽已知密码、token、Authorization、Cookie 等字段；不承诺任意业务日志完全无敏感信息，导出提示用户检查项目路径和业务内容。

## 4. 配置文件与保存规则

GUI 启动方式：`lan_codex_desktop --config=./lan_config.toml`；Windows 可双击 `lan_codex_desktop.exe`，macOS 可双击对应 `.app`。

默认读取发行目录旁的 `lan_config.toml`。macOS 以 `.app` 外侧的发行目录为准，不写入签名包内部。显式相对路径相对于调用者工作目录，与现有 CLI 一致。

桌面专用设置独立存放在所选 LAN 配置目录旁的 `desktop_config.toml`，保存 frpc/cloudflared 配置路径、程序路径及 Tunnel 启动模式。LAN 服务解析器不需要理解这些桌面字段。

- frpc token 仍写在用户自己的 `frpc.toml`，不复制到桌面状态文件。
- Cloudflare token 单独保存在用户选择的本地 token 文件，通过程序支持的 token 文件选项传递。所选版本不支持时给出升级/本地 YAML 模式指引，不退回到明文 token 命令行。
- 桌面设置里的相对路径以桌面设置所在目录解析；被管理服务的相对路径行为保持与原 CLI 一致。
- TOML 使用保留注释和未知键的文档模型；YAML 原始编辑采用安全解析，不允许对象构造标签。
- 验证通过后，写同目录临时文件，再原子替换目标。保存前检查原文件内容摘要；外部修改时提示重新加载，不静默覆盖。
- 目标不可写时提供另存为，不提升权限，不改系统目录权限。不得自动覆盖已有配置。
- 临时文件、私有配置、凭证、下载的二进制和日志全部忽略；发行包只包含空密钥的示例。

## 5. 进程控制与关闭

界面与管理逻辑分离：Qt 窗口 → 进程控制器、配置编辑器、组件安装器、日志缓冲区。阻塞操作都不在 GUI 线程执行。

每个受控进程记录自身创建的句柄、PID 和创建时间。不根据进程名、占用端口或旧 PID 文件接管/结束其他进程。发现外部已有服务时报告冲突，由用户处理。

- 使用参数数组启动，禁止 shell 拼接。Windows 子进程隐藏控制台窗口。
- Share 作为独立子进程运行，不与 GUI 共用生命周期线程。
- 为 GUI 子进程添加仅继承管道可用的内部 worker 入口：stdin 接收固定的停止命令，stdout 发送就绪/退出事件，日志独立处理。不给远程网页暴露停止接口。
- 对现有 Share 启动函数增加可选停止事件/就绪回调，默认路径行为不变；服务停止从其他线程触发 `shutdown()`，避免 `serve_forever()` 同线程死锁。
- 停止优先让现有 HTTP、Session hub 和所属 App Server 清理执行。15 秒未结束则提示仍在清理，允许用户继续等待或明确强制停止受控进程；不自动无限重试。
- 不对业务子进程做无差别递归杀进程。需要强制结束时，仅针对可验证归属的桥接服务和所属 App Server，不涉及用户外部启动的业务服务。
- frpc/cloudflared 使用平台可用的正常终止机制；确需强制结束时仅操作创建的进程句柄。Windows 的终止语义需实测，不把强制终止标成“优雅关闭”。
- 关闭 GUI：无运行服务时直接关闭；有服务时提供“取消”和“停止本客户端服务并退出”。首版不提供关窗后继续后台运行。
- 下载中关闭需要确认取消，清理本次下载的临时文件；配置未保存时先提示保存或放弃。

## 6. frpc 下载与安装

按当前平台及 CPU 架构选取 `fatedier/frp` 官方 GitHub 发行版，仅稳定版，显示选定版本后由用户点击安装。

1. 获取官方 release 元数据，设置超时、重试上限和取消能力。
2. 选择严格匹配平台/架构的归档，不凭文件名模糊匹配；不支持的平台直接提供官方下载页。
3. 从官方发行元数据或同版校验文件获取 SHA-256，再校验下载内容。缺少可信摘要时禁止自动安装，转为手动下载指引。
4. 下载大小限制 200 MiB，提取的 frpc 限制 100 MiB；仅提取预期二进制，拒绝路径穿越、绝对路径、符号链接和非普通文件。
5. 校验通过后原子放入配置目录旁的 `bin/frp/<version>/`；不覆盖正在运行的程序，只有安装成功才更新所选路径。
6. 失败清理本次临时文件，旧程序和原配置保持不变。无足够磁盘空间、代理网络或 GitHub 限流时显示可操作的提示。

网络请求仅限官方 API、发行页与经允许的官方 release 资产域；不接受任意 URL 下载执行。不得关闭 HTTPS 证书验证。

## 7. 安全约束

- 不更改现有公网入口访问规则；HTTP FRP 入口仍要求项目密码，并提示浏览器到公网服务器这一段不加密。
- FRP 和 Cloudflare 入口配置互相独立；配置入口地址不等于连接隧道。
- 本地控制台不会自动启动任何隧道；点击启动才建立所配置的连接。
- 日志和错误不输出完整命令环境、token、密码或凭证内容。配置明文文件必须在 UI 中说明，不将普通本地配置伪称为加密保险箱。
- 下载操作、停止操作与保存操作使用各自明确状态，失败不能显示完成。

## 8. 发行与兼容

一个平台发行 ZIP 同时包含现有 Share/CLI 可执行程序、桌面客户端和示例配置；仍是“下载一个包即可选择 GUI 或命令行使用”。GUI 采用目录型打包，避免每次启动展开完整 Qt 库。

- Windows x64：无控制台 GUI `.exe`，原 console `.exe` 保留。
- macOS x64 / ARM64：GUI `.app` 与现有 CLI 同包。
- Linux x64 / ARM64：GUI 可执行目录与 CLI 同包；无桌面环境时 CLI 照常运行，GUI 明确报告显示环境缺失。
- 包内 GUI 依赖、平台插件和 Qt 第三方许可一并收集；排除未使用的 WebEngine 等大型模块。许可证分发要求在打包阶段检查。
- 未配置签名/公证时不得声称应用已签名或已公证；文档说明系统可能提示来源未知。
- 版本号与发布说明待实际实现和验证完成后确定。本次确认不等于授权立即推送或发布。

## 9. 验收与实现顺序

先完成 Windows 本地可运行版本，再接入五平台构建与验证；没有验证的平台明确标注，不用 Windows 结果代替其他平台结果。

验收范围：

1. 原有自动化测试、默认 CLI 和 `--config` 回归通过，未安装 Qt 时原入口可运行。
2. 通过临时目录、假程序和回环测试服务验证启停、失败、并发点击、超时退出、PID 重用防护；不使用真实 frps 凭证。
3. 配置注释/未知字段/多个代理保留，端口错误和语法错误阻止写入，外部改动不被覆盖，中文与带空格路径正常。
4. 不记录或导出已知敏感值，长日志、分段 UTF-8 和高频输出不会卡住窗口。
5. 下载缺失摘要、错误摘要、超限、路径穿越、网络失败及取消均不执行安装、不破坏旧程序。
6. GUI 在桌面常见分辨率和高 DPI 下无裁切；最小窗口 900 × 640，内容可滚动，键盘可操作并有可见焦点。
7. 构建后的 GUI/CLI 来自同一版本；干净目录默认配置、显式配置、缺少依赖、退出清理与发行包内容检查均通过。

自审结果：布局已经确认；技术方案、目录规则、窗口关闭语义、未安装组件处理和不公开桌面管理能力均已写明。未包含真实服务器地址、真实 token、用户绝对路径或私有配置。
