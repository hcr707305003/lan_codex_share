# 隧道配置保存与 Share 公网入口同步

日期：2026-09-16。状态：已确认并完成实现、测试及界面验证；当前分支保留，未提交、打包或发布。

## 目标与边界

目前控制台保存 frpc.toml 或 Cloudflare YAML 只更新当前文件，不更新 lan_config.toml，导致已设置转发但公网按钮仍不可用。补充明确、可验证的联动保存，不改变命令行脚本的启动行为，不启动、停止或重启任何服务。

只在控制台对当前选定的 FRP / Cloudflare 配置执行“校验并保存”时触发。另存副本、保存 Share、扫描外部进程和打开窗口不触发同步。组件 Token 模式仅提供手动入口提示，不解码 token、不请求远程配置、不访问 Cloudflare API。

## 候选入口生成

### FRP

- 从保存后的 FRP 文档读取 serverAddr 和 TCP proxies。
- 仅接受明确回源本机回环地址（127.0.0.1、localhost、::1）、localPort 等于当前 Share Web 端口的映射。其他端口、远端主机、非 TCP 或插件代理不作为候选。
- remotePort 必须为有效端口；serverAddr 必须满足现有 FRP 入口校验。当前服务器 IPv4 + 端口模式生成 `http://服务器IP:remotePort`；现有 Share 不支持 HTTP 公网 IPv6，因此公网 IPv6 不生成候选，明确提示不支持（IPv6 回环回源仍可识别）。不把 serverPort 控制端口用于浏览器地址，不通过 DNS 猜测域名对应的 IP。
- 候选去重；显示映射信息供选择，不展示 token。没有可靠候选则保留当前入口，提示在 Share 配置手动填写。

### Cloudflare YAML

- 仅在当前选择本地 YAML 启动模式时，从 ingress 中提取指向 `http://本机回环地址:Share端口` 的规则。
- hostname 必须是明确域名，不接受通配符；规则不得限制 path。忽略 catch-all、非 HTTP、其他端口、其他主机及其他服务。
- 生成 `https://hostname` 候选并去重。多个候选让用户选择，不选则保持原入口。没有候选或 Token 模式时明确提示手动填写 cloudflare_origin，不清空已有入口。

## 写入与冲突

1. 按现有逻辑校验和保存当前隧道配置，保留注释及外部修改检测。
2. 读取并校验当前 LAN 配置，生成候选。只允许修改对应的 frp_origin 或 cloudflare_origin，保留密码、权限、Session、其他入口和未知字段。
3. 对应入口为空且只有一个候选：自动填入；对应入口与候选相同：无需重复写入。
4. 对应入口非空且不同，或存在多个候选：显示旧值、候选和同步影响，允许选择确认或取消，默认不覆盖。取消只跳过入口同步，隧道文件仍已保存。
5. 兼容旧 public_origin：不能与新字段混用。采用现有兼容规则（HTTPS 归 Cloudflare，HTTP 归 FRP）迁移并保留原入口；若迁移目标与本次候选冲突，走同一确认流程。成功迁移时删除旧字段，不静默丢失原入口。
6. 使用现有 ConfigDocument 原子替换及摘要检测写入 LAN 文件，写入前执行完整 LAN 校验。HTTP 公网入口仍要求非空项目密码；不能为方便同步而取消校验或自动设置密码。
7. LAN 配置无效、密码缺失、文件被外部修改或写入失败时，保留原 LAN 文件，明确显示“隧道配置已保存，Share 入口未同步”及不含敏感内容的原因。不回滚用户已保存的隧道配置，不报告两份文件均已更新，不假装两文件保存是原子事务。
8. 完成后刷新卡片地址、按钮及配置变更提示。提示所涉及的运行服务需用户自行重启生效；不自动重启。

## 实现结构

新增不依赖 Qt 的候选提取与入口更新准备模块，复用现有 LAN 校验、ConfigDocument 及 URL 校验。ConfigPage 负责保存后协调和冲突选择，DesktopWindow 只接收变更通知并刷新入口；避免把解析或文件写入放入定时 UI 刷新。
