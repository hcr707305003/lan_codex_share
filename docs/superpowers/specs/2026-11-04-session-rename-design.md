# 当前共享会话重命名

## 已确认方向

用户要求在网页重命名当前会话，并写回 Codex 的真实会话名称，不设置独立网页别名。

## 交互

- 当前会话右上角任务菜单增加“重命名”。
- 沿用页面深色弹窗样式，预填当前名称，提供保存和取消；输入获得焦点。
- 名称去除首尾空白后不能为空，最多 100 个 Unicode 字符，不允许换行和控制字符；前后端一致验证。
- 打开弹窗时固定目标 Session ID，保存过程中禁止重复提交。切换会话不会误改新会话。
- 保存成功后关闭弹窗，并刷新标题、左侧共享任务及其他访问者的实时状态。
- 保存失败保留输入和弹窗，展示可理解的错误。接口不支持时明确提示升级 Codex，不降级为网页别名。

## 数据链路

- 新增 POST /api/session/rename，接收 session_id、name。
- 沿用现有项目认证、CSRF、请求体大小限制与共享名单校验。
- 经 Session Hub 定位指定会话，调用 Codex 客户端的 thread/name/set，参数为 threadId 和 name。当前 codex_client.py 已在创建会话时使用该接口。
- 仅在接口成功后刷新名称元数据并广播；不替换历史投影、不创建或重新开始会话、不修改 session_ids。
- 不在全局 Hub 锁内等待远端 RPC。对名称目录刷新与重命名之间的旧结果覆盖进行回归验证。
- 重命名不取消任务、不清理队列；会话移出共享或不存在时拒绝修改。

## 验证

- 客户端：正确 RPC 方法、Session ID、名称，错误不吞掉。
- 接口：空白、过长、控制字符、非字符串、不在共享列表、未认证及 CSRF 错误均拒绝。
- 状态：成功更新对应名称；失败保持原名；其他会话及历史/队列不变；目录刷新不立即覆盖已成功的新名称。
- 网页：预填、取消、重复提交、失败保留输入、切换会话时目标固定；多客户端通过现有事件流收到更新。

## 范围

只改 lan_codex_share；不重启服务，不修改 PHP，不自动提交推送或发布新版本。
