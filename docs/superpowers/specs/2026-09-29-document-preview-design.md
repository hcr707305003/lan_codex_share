# 已上传文档点击预览

日期：2026-09-29

状态：交互方案已获用户认可；书面规格待确认。当前分支实施，只改本地，不推送、不发布、不操作现有服务。

## 目标与选择

在已发送消息的附件卡片上点击文件名，即可在现有右侧文件预览栏查看内容，保留独立的原文件下载入口。不要求先下载再用其他软件打开。

采用复用预览栏与现有安全文本提取的方案。相比引入 Office 转换服务完整还原 Word 版式，该方案不需要安装 Word、LibreOffice 或第三方在线文档服务，适合现有跨平台发行方式。明确不承诺 Word 原始版式。

本次仅覆盖已提交并绑定 Session 的附件。待发送附件仍使用现有选择、移除流程；不新增上传前预览、在线编辑、OCR、旧版 DOC 支持或其他文件格式。

## 交互与格式

- 文件名使用可键盘操作的预览按钮，不将整张卡片包成包含下载链接的嵌套交互元素。缺失附件保留名称与错误提示，禁用预览。
- 点击后复用现有右侧面板，显示文件名、大小、加载状态、关闭、刷新与下载；不显示服务器磁盘路径。
- MD 使用现有安全 Markdown 渲染器，保留标题、列表、表格与代码块；不执行原始 HTML、脚本或自动加载文档中的远程资源。
- TXT 展示可换行的纯文本。DOCX 展示提取的段落与表格行列文字，保留换行和制表分隔，并提示“文本预览，不保证还原原始版式”；不把 DOCX 正文当 Markdown 或 HTML 执行。
- PDF 使用浏览器内嵌查看原始文件；浏览器不支持时提示下载，不保证所有移动浏览器均可内嵌。
- 刷新页面后再次点击历史附件仍可预览。关闭、切换 Session、快速点击不同文件时，旧请求不得覆盖新面板，不得显示上一会话的附件。
- 下载按钮仍下载原始字节，点击下载不触发预览。图片灯箱及工作区代码/文档预览保持原有行为。
- 使用现有桌面/手机面板布局；长文件名、长行、长表格由面板内部滚动，不能撑开主布局或把顶部挤出屏幕。

## 接口、存储与权限

- 新增按附件 ID 和 Session 请求预览的接口，与现有附件下载入口分离。文本返回名称、大小、预览类型、正文与提取提示；PDF 返回正确 MIME 和 inline 响应，不改变下载接口 attachment 语义。
- 先执行现有登录、Host/来源与 Session 范围校验，再通过 DocumentStore 查找该 Session 下的随机附件 ID；不接受任意文件路径，不借此扩展 preview_roots。
- 原文件不存在时返回明确错误，即使有文字缓存也不伪装文件仍可用。未知 ID、错误 Session、路径穿越均拒绝。
- MD/TXT/DOCX 预览内容可复用有界提取结果，在文档存储层持久化缓存；只在用户打开预览时返回正文，不将全文增加到 snapshot、SSE 或聊天历史载荷。
- 兼容此前已上传但没有提取缓存的附件：首次预览时通过现有受限解析进程读取原文件并缓存。保持现有大小、文本字符数、30 秒超时、单解析进程与内存监测限制；繁忙/损坏/超限返回明确错误，重试由用户点击刷新触发。
- 缓存仅属于单个附件，排队取消清理时随该附件删除；不修改已发送给 AI 的输入，不触发新的 AI 任务。
- 预览沿用 no-store 与 nosniff 等安全响应头。Markdown 仅使用安全 DOM 输出与链接协议校验，不启用文档脚本、宏、外部实体或第三方在线预览器。

## 代码边界

- DocumentStore 负责附件归属、原文件查找、文本缓存与旧记录兼容，继续复用 document_extract 的有界解析。
- lan_web 增加受保护预览路由，下载与预览分离，不将解析实现放入 HTTP 处理器。
- web/app.js 为面板引用区分“工作区文件”和“上传附件”；刷新、下载和异步结果校验根据引用类型分派，保留已有工作区行为。
- 附件名按钮与预览正文样式沿用既有设计；README 说明各格式效果与 DOCX/PDF 限制。
- 不修改私人配置、不新增安装依赖、不重构无关上传、队列或反代功能。

## 验收

1. MD、TXT、DOCX、PDF 上传后点击预览，原文件下载仍字节一致；只有附件的消息与文图混合消息均可用。
2. 新附件、旧无缓存附件、服务重新创建存储实例、刷新和历史消息均可读取；提取缓存不会进入历史 snapshot。
3. 缺失、损坏、超时、繁忙、错误 Session、未登录和伪造 ID 均给出正确拒绝或提示；恶意 Markdown/文件名不能执行 HTML/脚本。
4. 快速切换文件、关闭面板、切换 Session 时无异步串内容；已有工作区预览、图片点击放大、下载不回归。
5. 在真实浏览器验证桌面与窄屏的打开、关闭、刷新和下载，确认长内容不影响聊天顶栏与滚动。
6. 自动化测试使用合成文档与假模型，不读取真实私人文档、不创建真实 AI 任务；最终运行相关 Python/JavaScript 回归和 diff 检查。
