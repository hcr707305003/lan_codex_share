# 文件预览下载设计

## 目标

在右侧文件预览面板中增加当前文件下载能力。用户查看 Markdown、代码、图片或 PDF 时，可以直接保存该文件，并保留原文件名；下载行为不得扩大现有工作区文件访问权限。

## 范围

- 只允许下载当前已经通过文件预览校验的文件。
- 继续限制在工作区和 `preview_roots` 配置的授权目录内。
- 继续复用文件预览支持的类型与大小上限，不开放任意二进制文件或超限文件下载。
- 不增加批量下载、目录下载、压缩打包、另存为命名或下载历史。
- 不改变 Session、消息队列、文件预览渲染或权限配置结构。

## 界面与交互

- 在文件预览标题栏操作区增加独立下载图标，固定顺序为“刷新 → 下载 → 关闭”。
- 下载按钮与现有图标按钮使用同一视觉语言、悬停态、焦点态和可访问名称。
- 桌面端保持紧凑图标；窄屏下触控区域至少为 `44px × 44px`。
- 未打开文件、文件仍在加载或预览失败时，下载按钮不可用。
- 当前文件成功加载后，下载按钮指向该文件的下载接口。
- 点击后使用浏览器原生下载行为，不打开新标签页，并使用服务端返回的原文件名。
- 下载失败不会清空、关闭或替换当前文件预览内容。

## HTTP 接口

新增只读接口：

```text
GET /api/files/download?path=<workspace-file-path>
```

接口行为：

1. 对请求执行现有局域网访问、Host、Origin 和可选密码认证校验。
2. 使用 `WorkspaceFileViewer.open()` 解析路径并执行授权目录、文件类型、文件大小及普通文件校验。
3. 校验成功后读取文件字节并返回对应 MIME 类型。
4. 设置 `Content-Disposition: attachment`，通过 UTF-8 文件名参数保留中文、空格及其他非 ASCII 文件名。
5. 返回准确的 `Content-Length`，由浏览器执行原生保存。

下载使用独立接口，不向预览接口增加模式参数，从而保持“在线查看”和“保存文件”的 HTTP 语义清晰。

## 权限与安全边界

- 下载接口与 `/api/files/view` 使用完全相同的路径解析器，不单独拼接或放宽路径。
- 目录越界、文件不存在、非普通文件、不支持类型和文件过大继续返回现有对应错误。
- 配置了共享密码时，下载接口必须携带有效认证 Cookie；未登录返回 `401`。
- 文件路径仍只通过查询参数传入，不信任前端保存的预览状态。
- 响应强制使用附件语义，避免下载接口执行或内联渲染文件内容。

## 前端状态流

1. 页面初始化时下载控件处于不可用状态，不包含旧文件地址。
2. `openFilePreview` 开始加载新文件时，先清除下载地址并禁用控件。
3. 文件预览成功后，根据已规范化的当前文件引用生成下载 URL 并启用控件。
4. 文件预览失败或预览面板关闭时，清除下载地址并恢复不可用状态。
5. 切换 Session、刷新预览或快速连续打开多个文件时，仅最新预览请求可以启用下载控件，避免下载到旧文件。

## 错误处理

- 下载请求的路径或权限错误由服务端返回统一 JSON 错误和对应 HTTP 状态码。
- 浏览器原生下载无法在当前页面内可靠读取导航错误，因此前端只在预览成功后开放下载入口，尽量在发起请求前消除已知错误。
- 下载期间发生文件删除、权限配置变化或文件大小变化时，以服务端下载时的再次校验结果为准。
- 下载错误不修改右侧面板的标题、路径、滚动位置和已渲染内容。

## 可访问性

- 下载控件提供 `aria-label="下载当前文件"` 和可见工具提示。
- 不可用状态不能通过鼠标或键盘触发。
- 保留现有键盘 Tab 顺序：刷新、下载、关闭。
- 使用现有可见焦点样式，不只依赖颜色表达可用状态。

## 验证

- 接口测试确认下载内容与源文件字节一致，并返回附件响应头和准确长度。
- 覆盖中文、空格及非 ASCII 文件名编码。
- 覆盖目录越界、缺失文件、不支持类型、超限文件和可选密码认证。
- 页面结构测试确认下载控件位于刷新与关闭之间，并包含可访问名称。
- 前端测试确认预览加载、成功、失败和关闭时的下载状态切换。
- 执行 JavaScript 语法检查、目标 Python 测试和完整测试套件。
- 桌面与窄屏手工验证按钮位置、44px 触控区域、原生下载文件名以及下载后预览不变。
