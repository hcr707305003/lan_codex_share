# 桌面控制台视觉统一、多主题与应用图标设计

日期：2026-09-16

状态：已实施；579 项回归测试通过，Windows 普通/高 DPI 截图检查完成。保留本地改动，未打包或发布。

## 1. 目标与约束

统一 LAN Codex Share 原生桌面控制台的四个页面、状态、表单、日志和弹窗，提供四套内置主题及可持久化的外观设置，并为客户端和后续各平台分发包接入同一应用图标。

- 保持 PySide6 原生桌面实现，不嵌入网页、不迁移框架、不引入在线字体或主题 CDN。
- 当前分支原地开发，保留现有未提交功能及用户配置。
- 本次不提交、推送、打包或发布版本；只接入未来打包所需的资源与构建配置。
- 不自动启动、停止或重启现有 Share、FRP、Cloudflare、PHP 或业务服务。
- 不改变进程归属、外部进程识别、强制关闭复核、配置校验、公网入口同步、下载确认等功能和权限边界。
- 不同步改变浏览器端共享会话界面；本次仅桌面控制台。

## 2. 已确认的视觉方向

用户确认了本地视觉预览中的布局、图标，以及“所有主题都保留、再增加主题并在设置中选择”的方案。

参考预览：`.superpowers/brainstorm/1267-1789548722/content/console-theme-settings.html`。该文件是忽略的本地设计参考，不是运行资源；以下规格独立描述实现要求。

布局、尺寸、功能和信息结构完全一致，仅替换语义色彩。四套均为正式内置主题，不要求用户在实施前只选一套。

运行成功、警告、失败拥有独立语义颜色，不能直接复用蓝色或紫色主题强调色表示成功。状态始终配文字，不仅靠颜色表达；未知或未验证状态不表现为已连通。

### 2.2 排版与控件

- 清晰层级：页面标题、分区标题、正文、辅助信息、等宽日志；避免所有内容相同字重。
- 中文使用平台可用的无衬线字体回退，日志/端口使用平台等宽字体；不要求安装新字体。
- 间距以 4/8 像素为基准，卡片与内容区采用统一内边距，圆角控制在 6–12 像素。
- 降低重复描边密度，不使用发光、玻璃模糊、持续动画或无意义渐变。
- 图标统一矢量线性风格；图标按钮有工具提示和可访问名称，不能只靠图形猜含义。
- 常规文字对比度目标至少 4.5:1；焦点和有意义的控件边界独立可辨。实际测量不通过时可微调同主题色值，不改变视觉方向。
- 保持窗口最小尺寸 900×640；900×640 与 1280×800 均可用。长路径、域名、错误详情可换行、截断加完整提示或局部滚动，不顶出按钮。
- 保留系统窗口标题栏和系统文件选择器，不实现自绘拖动、最大化等窗口行为。

## 3. 页面覆盖

### 3.1 导航与服务总览

保留左侧四个主导航：服务总览、配置管理、组件管理、运行日志。侧栏顶部使用统一应用图标和名称，底部新增独立“外观设置”入口。

三个服务卡片保留 Share、frpc、Cloudflare。顺序为服务标识与状态、用途简述、端口/来源信息、可打开的入口、主要操作与配置入口。

- Share 显示本地监听端口、进程来源和已验证 PID。
- FRP 区分服务器控制端口、本地端口、公网业务端口；“进程运行中”不等于公网可达。
- Cloudflare 区分停止、本客户端运行、外部运行、配置未确认等状态。
- 公网入口继续使用现有 entries 模块的校验结果；无有效入口时禁用打开操作并说明原因。
- 主操作依据真实状态显示启动、停止或需要确认的强制关闭；外部隧道不可因改版新增停止权限。
- 配置入口可使用次级图标按钮，保留明确工具提示。
- 下方保留运行说明、最近日志和概要状态；不添加虚构性能统计。

### 3.2 配置管理

保留 Share/FRP/Cloudflare 切换、配置路径、打开/创建示例/重载、表单和原始配置、另存副本与保存。

重排为页头与文件操作区、编辑区、保存与反馈区。保留未保存提示、密码隐藏、外部文件变更检查、FRP 多代理选择及公网入口同步流程。路径不能挤占保存按钮。

### 3.3 组件管理

按 frpc、cloudflared 组件分组显示发现路径、版本/发现状态、选择本地程序、下载入口。全局扫描/检测与下载进度、取消操作清晰分组。Cloudflare 启动模式和 token 文件另设分区。

不改变下载目的地、签名/校验策略、候选路径选择、安装确认或下载后不自动启动的规则。未保存的 Tunnel 设置仍须防止静默丢失。

### 3.4 日志

统一搜索、服务筛选、暂停、清空、导出按钮层级，日志区使用主题适配的等宽字体、背景与选中颜色。保持日志长度限制、脱敏和暂停语义，不因主题切换重新读取或清空日志。

## 4. 外观设置与持久化

外观设置以独立对话框展示四个主题缩略图、名称、当前选中状态和完成按钮。

- 点击主题立即更新当前应用内所有页面、控件与弹窗，不重启任何服务。
- 使用已有 `DesktopSettings` 管理的 `desktop_config.toml` 保存 `theme = "graphite"` 等稳定 ID；配置位于所选 LAN 配置同目录。选择另一配置目录可以拥有自己的偏好。
- 默认值为 graphite；未提供主题或主题 ID 未知时回退 graphite，不覆盖原配置值。主题字段类型异常只回退主题，不因外观字段阻止服务控制台启动；其他配置错误维持原处理规则。
- 保存时只修改主题字段，保留可执行文件路径、Tunnel 模式、注释和其他未知字段，不写入 `lan_config.toml`、`frpc.toml` 或 Cloudflare 配置。
- 先成功保存再确认应用新主题；保存失败显示明确错误，保留旧主题与选择状态，不误报“已保存”。
- 每次启动读取并应用已保存主题；设置关闭不提示放弃修改，因为选择已即时保存。
- 本机偏好不发给共享网页用户、不成为服务任务上下文。主题切换不触发“服务配置已变更，需要重启”的标记。
- 本次不增加跟随系统、主题编辑器、下载第三方主题、字体缩放或主题云同步。

## 5. 弹窗统一

覆盖停止服务、强制关闭外部 Share、退出并停止自管服务、公网入口覆盖/候选选择、未保存修改、安装确认，以及一般错误/警告/信息提示。

- 统一主题、图标、标题、正文、详情区和底部按钮；一般成功反馈优先沿用页面内状态提示，避免额外打断。
- 危险确认默认选中取消/否，Enter 默认取消，Esc 退出；确认按钮使用明确动作名称，而不是单独“确定”。
- 强制关闭与正常停止使用不同标题、影响范围和警告文案，不隐去现有验证信息。
- 参数、路径、错误等动态文本按纯文本显示，不作为富文本或链接执行。
- 长文本可换行/滚动，按钮保持可见；键盘焦点不跑到后面的页面。
- 安装包/文件选择窗口使用平台原生选择器，属于明确例外，不强行改成自绘文件管理器。
- Qt 依赖尚未加载时的启动错误继续保留现有系统兜底提示；不要求该兜底使用自定义主题。

## 6. 统一应用图标

采用已确认的独立图标：深绿圆角方形底、薄荷色终端提示符与连接节点。图标在四种主题间保持不变；不使用 OpenAI 官方标志。

- SVG 为可维护源文件，带可访问标题，不包含字体、远程资源或位图嵌入。
- 在 16、24、32、48、64、128、256、512 像素检查辨识度，优先保持小尺寸轮廓清晰。
- 从同一矢量源生成 PNG、含多尺寸的 Windows ICO、macOS ICNS；导出脚本可离线重复运行，不能要求 AI API 或网络密钥。
- 接入 QApplication/窗口图标；Windows 设置稳定应用标识，使后续桌面包任务栏图标一致。
- 桌面 PyInstaller EXE 接入 ICO，macOS BUNDLE 接入 ICNS，Linux Qt 窗口使用 PNG/SVG。
- Windows Share 命令行可执行文件的文件图标也使用同一 ICO；不修改用户已安装的 Codex CLI 二进制及其标识。
- 图标运行资源包含在打包数据和必要的包资源声明中，源码运行与冻结程序均可解析，不依赖启动工作目录。
- 修改构建配置与打包相关说明，不执行发布流水线或生成新发布包。

## 7. 实现边界

- `desktop/theme.py`：主题注册、语义配色、Qt palette/QSS 应用；不依赖服务状态。
- `desktop/appearance.py`：主题选择界面和设置保存/失败回退；不混入服务启动逻辑。
- `desktop/config.py`：在现有 DesktopSettings 上扩展主题字段，避免新增第二套偏好存储。
- `desktop/icons.py` 及包内 assets：统一应用图标与可主题化的界面图标加载。
- `desktop/window.py`、`config_page.py`、`components_page.py`：定向布局和控件层级调整，不重写后台监控/进程生命周期。
- `desktop/dialogs.py`、`origin_dialog.py`：统一弹窗样式及共用提示入口，保留每种操作原有业务确认条件。
- `desktop/app.py`：启动时应用主题与应用图标，保留 Ctrl+C 与 smoke-test 行为。
- 构建 spec、资源导出脚本、测试、`desktop_config.example.toml` 和 `DESKTOP.md`：更新与本功能直接相关的部分。

主题应用仅发生在初始化或用户切换时，不放入周期刷新。监控线程不读写 QWidget，不重复构造页面或重置用户输入。

## 8. 验收

### 自动化

1. 四个稳定主题 ID、默认主题、未知 ID/类型回退及主要色彩对比度。
2. 主题读写往返，保留其他设置和注释；写入失败不应用新主题、不丢失原文件。
3. GUI 主题切换更新已有窗口/弹窗，关闭重开恢复；不改变服务进程、日志、配置草稿和公网入口。
4. 外观字段保存不标记服务待重启；一般提示、危险弹窗 Enter/Esc/默认焦点行为不回归。
5. 图标源与导出文件存在且可解析；运行资源路径不依赖 CWD，构建 spec 引用一致。
6. 全量现有测试回归，尤其是外部 Share 强制关闭、外部隧道检测、入口同步、下载取消和 Ctrl+C。

### 可视检查

- 使用临时配置、模拟状态和 offscreen Qt 截图，不连接或操作用户当前服务。
- Windows 本机检查四套主题的总览、配置、组件、日志和主要弹窗；覆盖 900×640、1280×800 与高 DPI 场景。
- 验证长路径/长错误、正在启动/停止、未验证外部状态、禁用按钮和键盘焦点。
- macOS/Linux 如无法本机执行，只报告构建接线/静态检查结果，不声称已完成原生平台视觉验收。
- 测试截图不包含真实令牌、密码、服务日志或业务资料；新增截图与诊断产物不混入发布资源。

## 9. 书面自检

- 范围为一个桌面外观子系统；没有增加联动启动、自动联网或外部隧道停止功能。
- 四套主题全部保留，选择只影响本机控制台；不存在选一套后删除其他方案的歧义。
- 即时切换与保存失败处理一致：保存成功才应用，失败保持旧选择。
- 原生文件选择器与依赖加载失败兜底是有意保留的主题例外。
- 本次仅接入未来打包使用的资源，不构建/提交/发布；测试不操作真实服务。
