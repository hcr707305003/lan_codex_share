# 网页新任务入口：选择已有会话或新建 Session

日期：2026-09-29

状态：用户已确认书面规格，已在当前分支实现并通过本地回归与模拟浏览器验证。未修改运行中的服务或私人配置，未打包、推送或发布。

## 目标

通过左侧“新任务”入口选择已有 Session，或在所选项目工作目录新建独立 Session，加入左侧共享任务。不是往当前任务发送指令，也不是仅更新顶部下拉框。添加或创建后刷新页面或重启 Share 仍然保留。

## 现状与选择

当前左侧“新任务”按钮禁用。全部发现模式已有项目分组导航，但指定 Session 模式只更新顶部下拉框，左侧仍是当前任务的单个占位条目。LanSessionHub 的静态服务集合目前不能动态添加会话。

采用服务端独立持久化的补充共享列表：与配置中的共享范围合并，所有访问同一 Share 实例的用户看到同一列表。

- 相比只存浏览器本地，该方式支持多人同步及换浏览器访问。
- 相比直接重写 lan_config.toml，该方式不与控制台配置编辑争抢写入，不改变空数组发现全部和缺省自动单会话的语义。
- 提供统一入口中的“已有会话”和“新建会话”两种操作，比两个独立按钮更容易发现，同时避免把选择已有会话误认为创建。也不采用仅支持手动输入 ID 的初版方案。
- 不增加删除、归档或重命名已有 Session 功能。本次不增加网页移除共享入口；维护补充列表可在停止 Share 后编辑运行时文件，README 明确路径与范围。

## 界面与交互

1. 启用左侧“新任务”按钮，弹框分“已有会话”和“新建会话”，默认已有会话；沿用现有主题，不设计新视觉风格。
2. 已有会话按项目分组，按标题或 ID 搜索，展示标题、短 ID、项目和更新时间，标记已共享条目；选中后明确点击添加。保留完整 Session ID 输入方式，不接受 URL、文件路径或任意 RPC 参数。
3. 新建会话选择工作目录：默认当前任务目录，无法取得时默认 Share 配置的 workspace；可选择本机已有会话对应的项目。仅接受服务端核实过且仍存在的项目目录，不提供任意服务器路径输入或创建目录。当前项目、配置目录和其他项目去重。
4. 弹框说明“候选列表仅展示会话信息；添加或创建后，将向能够访问当前 Share 的用户共享此会话”。提交时显示进行中并阻止重复提交。候选请求可取消，过期搜索结果不能覆盖新结果；关闭弹框不提交任何操作。
5. 添加已有会话成功后关闭弹框、刷新左侧并提示，保持当前选中会话、历史、滚动和草稿不变。新建会话成功后自动打开新条目；原 Session 的草稿和待发送附件在切换后可恢复，不把原草稿当成新会话首条消息。附件正在提交时禁止创建提交和会话切换，避免中途串会话。
6. 左侧在所有配置模式下都展示完整共享列表，具有标题、短 ID、当前选中态和现有状态信息。能取得工作目录时沿用“项目 → Session”分组，不能取得时归入未分配项目。
7. 顶部原 Session 下拉框不再作为指定模式唯一导航；为避免重复入口，所有模式统一隐藏它，切换均由左侧列表或窄屏侧栏完成。
8. 重复 ID 为幂等成功，提示已在列表中，不重复生成条目或连接。其他浏览器只更新列表，不强制跳转。
9. ID 无效、不存在、不可读取、归档或工作目录不可用时显示明确错误；保留输入便于修改，不改变原共享任务。弹框支持 Esc、键盘操作、焦点恢复及窄屏布局。新建使用默认标题“新会话”，不要求额外输入标题。

## 范围与持久化

- 在现有配置对应的 runtime/lan 下增加 shared_sessions.json，保存版本和补充 ID 数组，不保存会话正文、密码或 Token；该目录已在 Git 忽略规则内。
- 有效共享范围为现有配置范围与补充列表的并集。指定列表保持原有条目；缺省自动单会话保持原来的默认会话；session_ids=[] 继续发现全部且合并去重。
- 候选接口允许具有当前 Share 访问权限的访客查看本机当前 Codex 账户的会话标题、ID 和项目信息。候选列表不返回历史正文，不恢复会话，也不改变共享范围；只在明确选中并添加后共享该 ID。README 必须说明候选元数据可见范围比原静态白名单更广，不声称仍完全隐藏未共享会话。
- 使用串行添加锁与同目录临时文件原子替换，持久化成功后再发布内存更新和广播。写盘失败返回失败，不产生仅在当前进程可见的“添加成功”。
- 重启时读取补充列表。个别会话失效仅标记该条目不可用，不影响已有正常会话或服务启动；损坏文件不静默覆盖，保留文件并给出可操作错误。
- 此列表独立于 lan_config.toml：在控制台修改 session_ids 不自动删除网页添加的 ID。README 明确说明，避免把配置白名单误解为仍是唯一共享来源。

## 后端边界与安全

- 增加 GET /api/sessions/candidates、GET /api/sessions/projects、POST /api/sessions/add 和 POST /api/sessions/create。候选与项目接口同样执行现有访问和登录校验，修改接口额外执行 Origin/CSRF 校验。新 ID 路由须放在现有 resolve_session_id 检查之前，否则会被现有白名单直接拒绝。
- 候选接口只返回有界元数据页（每页最多 50 项），弹框滚动加载；按标题/ID 搜索使用服务端元数据索引或带上限缓存，不在每次输入时遍历全部会话，也不调用 includeTurns=true。排除归档、临时和子代理线程，远端分页游标必须验证，失败保留原列表并可重试。项目目录来源只读元数据，不扫描整个磁盘。
- 沿用现有项目密码访问模型，不新增账号系统；有权访问该 Share 的访客可使用添加功能。弹框和文档明确该操作改变此 Share 实例的共享范围。
- SessionHub 提供独立添加入口；通过服务端 Codex 元数据读取验证 ID、标题和 cwd，不把前端标题或路径作为可信来源。
- 候选查询、已有会话验证和添加只读，不调用 thread/start，不发送消息、不重命名、不抢占会话写锁。已有会话按需连接，用户点击后才通过现有严格恢复逻辑加载；若被其他客户端占用显示原有错误，不强制停止外部进程。
- 新建接口仅在用户明确提交后调用 thread/start，使用服务端验证的工作目录和当前 permission_mode，不复用或清空当前会话，不调用 turn/start，不自动发送首条消息。成功后将返回的真实 ID 持久加入补充列表、广播并交给调用页面打开；其他页面不切换。
- 新建请求带随机 request_id，服务端在运行时记录请求状态与已取得的真实 ID；同一请求重试不能再次创建。调用前记录进行中，拿到 ID 后记录结果。RPC 超时或服务崩溃导致结果不明时不自动重发 thread/start，提示刷新候选列表确认，避免重复创建。
- 若已创建但共享列表保存失败，保留已取得的 ID 并明确提示“会话已创建，共享保存失败”，允许按该 ID 重试添加；不谎称回滚、不删除真实会话。服务端记录结果成功之前不向页面报告完整成功。
- 新增会话使用已有服务工厂和当前 permission_mode，每个 Session 保持独立队列、状态、附件归属与历史分页。恢复失败不得回退创建空会话。
- 不自动扩展文件预览白名单。新增元数据 cwd 不能直接使原先不允许访问的目录变成 preview_roots；目录授权继续遵循原配置及原发现模式边界。
- 快照和 SSE 广播共享列表变化，但不携带新增会话全文；不同页面各自保持选中 ID。
- 保留已有释放/重连行为。动态创建的服务纳入现有 close 清理，避免连接和工作线程泄漏。
- 不记录会话正文或密钥，错误输出不包含原始 RPC 敏感数据。标题通过文本节点渲染。

## 实现落点

- 独立共享列表存储模块：ID 读取、校验、去重、原子持久化；不复用只保存单个 thread_id 的 StateStore 数据结构。
- session_hub.py：动态补充条目、摘要、按需连接、更新广播与清理，兼容静态和发现两种现有模式。
- lan_main.py：注入补充存储、只读元数据查询和服务工厂；不重构无关启动或隧道管理。
- codex_client.py：复用现有 thread/list、thread/read 和 thread/start 协议，增加与当前活跃会话隔离的只读元数据和创建方法，不改变当前任务的 state.thread_id。
- lan_web.py：增加受保护候选、项目、添加和创建路由，返回精简结果。
- web/index.html、app.js 和现有样式文件：双模式新任务弹框、统一左侧导航和按会话隔离的页面内草稿，保持历史分页、队列、上传和预览行为。草稿仅在当前页面生命周期保留，不额外持久保存附件到浏览器。
- README：说明操作、共享范围、持久化位置、配置关系和无需重启添加。

## 验收

1. 指定一个 Session 的模式下添加第二个已有 ID，左侧立即显示两个独立条目，原任务仍选中；点击新条目后历史和队列按 ID 隔离。
2. 原有多个指定 Session 全部显示在左侧；自动单会话和发现全部模式也能正常添加、去重与切换。
3. 刷新、重建 Hub/存储实例和模拟重启后新增列表仍在；多人页面同步更新但不互相切换。
4. 并发重复添加只写一条；不存在、非法 ID、损坏存储、写盘失败、工作目录无效、连接占用均有明确结果，原任务不受影响。
5. 未登录、跨来源、缺少或错误 CSRF 请求正确拒绝；列出和添加已有会话不调用 thread/start，不意外扩大文件预览范围。
6. 候选列表支持项目分组、搜索、分页和已共享标记，取消不共享任何新会话；空列表、加载失败、快速切换查询与大量元数据时界面可用。
7. 新建默认当前工作目录，可选择服务端项目；伪造或消失的工作目录拒绝。一次明确提交只创建一个空会话，原任务与队列继续，新条目持久保存且仅调用页面自动切换。
8. 重复请求、新建超时、创建后存储失败正确处理；不自动再次创建，不删除已创建会话。原会话草稿和待发送附件切换后可恢复，不混入新任务。
9. 使用假 Codex 和临时配置做 Python/JavaScript 回归；真实浏览器验证桌面、窄屏、键盘操作、添加期间上传和历史滚动不串会话，不使用私人会话或创建真实任务验证。
10. 当前阶段不打包、不推送、不发布、不自动重启 Share、隧道或 PHP 服务。
