# 网页文档附件上传设计

日期：2026-09-28

状态：交互方案已确认；书面规格待用户复核。

## 目标与范围

在现有网页消息上传链路中增加文档附件，上传后不仅展示文件名，也将可提取的文本提供给 AI。只修改 lan_codex_share 项目，保持现有图片、队列、流式回复、多 Session、历史分页及项目密码行为兼容。

支持 `.md`、`.txt`、`.docx`、`.pdf`，扩展名大小写不敏感。旧 `.doc` 明确提示转为 `.docx`，不调用本机 Word 或自动安装转换程序。本次不支持 Excel、PPT、压缩包、OCR、宏执行及文档在线编辑，也不提交或发布新的发行版本。

采用服务端内置文本提取方案。仅保存原文件再让 AI 自行寻找解析工具虽改动较少，但依赖用户机器的工具、权限和模型行为，不能稳定保证文档可读，因此不采用。

## 用户交互

- 回形针选择和拖拽入口同时接收上述文档及现有图片，继续支持剪贴板图片。
- 待发送文档显示文件名、类型、大小及移除按钮，不使用图片缩略图渲染文档。
- 允许只有文档而无文字的消息，以及文字、图片、文档混合发送。
- 上传期间禁用重复发送；失败保留输入及附件，并显示具体文件与原因；成功才清空发送框。
- 排队区显示文档数量或名称，发送后的消息保留附件卡片及原文件下载入口。文件名按纯文本渲染。
- 浏览器刷新、实时同步和切换 Session 后附件卡片保持存在；发送成功后的附件记录随本地运行数据持久化，服务重启后仍可关联已有会话历史。
- 不新增可视化风格或独立文档预览器，沿用当前界面样式。

## 限额及校验

- 新增 `max_document_bytes`，默认 20 × 1024 × 1024 字节，可设置为 1 字节至 20 MiB；`max_documents` 默认 5，允许 1 至 20。单条消息文档总大小不超过 100 MiB；两者与图片限额独立。
- 前端从服务端取得限额，不能只修改前端放行；HTTP 请求上限包含文档、图片的 base64 膨胀和 JSON 开销，并保留硬性资源边界。
- 服务端校验文件名、扩展名、解码后的大小和实际内容；不直接信任浏览器 MIME，也允许文档浏览器 MIME 为空或通用二进制类型。
- 拒绝路径穿越、空文件、伪造格式、损坏 DOCX/PDF、加密 PDF。存储使用服务端生成的随机 ID，不用客户端文件名作为磁盘路径。
- DOCX 必须是有效 OOXML Word 文档，不解压到任意磁盘路径，不解析外部实体或获取外部链接；ZIP 最多 1,000 个条目，累计展开不超过 50 MiB，累计压缩倍率不超过 100 倍。
- PDF 最多 500 页。复杂格式解析放在可终止的独立进程中，单文件最多 30 秒、全服务同时最多一个解析进程；解析繁忙时明确提示稍后重试，不无限排队，也不阻塞消息状态查询。
- 文档提取结果每文件最多 100,000 字符，每条消息合计最多 200,000 字符。超出时明确拒绝发送并提示拆分，不静默截断后声称全文已读。
- 任一附件校验或解析失败，整条消息不入队，清理该次请求新建的文件，其他历史附件不受影响。

## 文本提取与模型输入

- MD/TXT：保留原文，支持 UTF-8（含 BOM）、带 BOM 的 UTF-16 及中文 GB18030；解码失败或明显二进制内容给出错误，不用替换字符静默损坏正文。
- DOCX：按正文顺序提取段落和表格内容，保留基本段落、行列分隔。图片、复杂排版、批注、修订和嵌入对象不承诺完整还原，界面及文档说明这一限制。
- PDF：按页提取文本并标注页分隔。纯扫描或无可提取文本的 PDF 提示需要 OCR 或转为可复制文字的版本；部分页面无文本时明确告知提取范围，不宣称包含图片内容。
- 在现有 `turn/start` 文本输入中追加有边界标识的文档正文及名称，现有图片继续使用 `localImage`。不假定存在未验证的上游通用文件输入类型。
- 明确区分用户问题与附件正文，提醒模型附件是待分析材料，不能将其中的指令自动当作用户请求。此提示不替代现有权限及服务端安全边界。
- 文档正文不放进高优先级的应用指令；不执行文档中的脚本、宏，不为解析修改用户会话权限或扩大工作目录。
- 为避免聊天历史冗长，网页显示用户问题和附件卡片，不重复铺开全部提取文本。关联依赖可靠的消息 ID 和持久化元数据，不能按正文相似度随意隐藏用户输入。

## 存储、下载与生命周期

- 独立的文档存储/提取模块负责原文件、提取结果与元数据，置于已忽略的 runtime 目录下。Git、发行包及日志不得包含用户文档正文。
- 文档记录包含随机 ID、原文件名、格式、大小、提取状态及 Session/消息关联；对外不暴露内部文件路径。
- 下载只按服务端登记的 ID 查找，沿用项目密码与请求来源校验，强制附件下载及安全响应头，不将上传的 Markdown/HTML 当页面执行。
- 关联按 Session 隔离，不能通过客户端任意路径取文件。该应用已有的项目共享密码仍是共同访问边界，不在此功能中新增用户账号系统。
- 取消尚未开始的排队消息或清空队列时，只清理相应任务上传的附件及元数据；保留已执行消息的原文件供历史下载。任务执行失败保留错误状态和已接收附件，便于排查。
- 服务重启不保证恢复原有内存任务队列，但已成功提交至上游会话的消息附件可从持久化关联恢复。历史附件在 runtime 保留期间有效；缺失时显示“文件已不存在”，不伪造恢复成功。

## 代码集成边界

- `web/index.html`、`web/app.js` 和相关样式：文件选择、校验提示、卡片及下载；沿用现有消息和实时同步结构。
- `lan_web.py`：扩展消息请求的文档字段、验证与受保护下载接口；旧请求缺少文档字段时等价于空列表。
- `lan_config.py`、`lan_main.py`：上传限额、存储及提取组件装配，请求预算。
- `session_hub.py`、`lan_service.py`、`session_projection.py`：队列传递、附件关联、历史恢复及取消清理。原有图片参数与行为保持兼容。
- 新增专用文档模块，避免继续把解析逻辑塞入 Web 处理器或现有图片存储器。
- 将解析依赖固定版本并纳入 CLI/桌面打包配置；更新示例配置和 README，不改私人配置、不启动或重启现有服务。

## 验收

1. MD/TXT/DOCX/PDF 分别上传并验证传入模型的提取文字；DOCX 表格及多页 PDF 有可读边界。
2. 仅文档和文图混合消息可入队；原有纯文字、图片、队列取消和流式回复测试不回归。
3. 验证类型伪造、空文件、超限、损坏文件、压缩膨胀、解析超时、扫描件和密码 PDF，错误清晰且请求不部分入队。
4. 刷新、切换 Session、多人同步、历史分页、服务重新建立会话投影后，卡片仍对应正确消息且不会重复展开正文。
5. 下载校验原文件字节和文件名；未登录、未知 ID、路径穿越和错误 Session 关联被拒绝。
6. 混合上传失败回滚和排队取消仅删除本任务资源，已完成附件仍可下载。
7. 测试使用合成文档与假模型，不发送真实私人文件、不启动实际 Codex 任务。运行自动化测试及网页交互检查，必要时做本地打包冒烟，不发布版本。
