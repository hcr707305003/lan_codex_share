# 可选密码认证设计

## 背景

局域网 Codex 共享服务当前只校验来源 IP、Host、Origin 与 CSRF。同一局域网内的任何人只要知道地址，就能查看共享 Session、文件和图片并执行已开放的操作。

本功能增加一个可选的共享密码。密码为空时保持现有无登录行为；密码非空时，浏览器必须先登录才能访问任何会话数据或操作接口。

## 配置

`LanConfig` 新增字符串字段：

```toml
password = ""
```

- `password = ""`：关闭密码认证。
- 非空字符串：启用密码认证，字符串按原值比较，不自动去除首尾空格。
- 非字符串配置视为配置错误，桥接器拒绝启动。

公开示例配置只保留空值。真实密码写入已被 Git 忽略的 `lan_config.toml`，README 不包含真实密码或本机路径。

## 认证模型

采用应用登录接口和浏览器会话 Cookie：

1. 桥接器启动时生成随机认证 token，仅保存在内存中。
2. 浏览器调用 `GET /api/auth/status` 查询是否需要登录以及当前 Cookie 是否有效。
3. 需要登录时，页面显示密码登录层，不启动 Session 快照请求和 EventSource。
4. 浏览器通过 `POST /api/auth/login` 提交密码。
5. 服务端用 `hmac.compare_digest` 比较配置密码，成功后通过 `Set-Cookie` 返回随机 token。
6. Cookie 使用 `HttpOnly; SameSite=Strict; Path=/`，不设置 `Expires` 或 `Max-Age`，因此属于浏览器会话 Cookie。
7. 浏览器关闭后 Cookie 失效；桥接器重启后内存 token 变化，已有 Cookie 也会失效。

Cookie 不设置 `Secure`，因为项目默认通过局域网 HTTP 访问。README 明确说明：密码认证可防止误入和普通未授权访问，但不能防止局域网流量嗅探；强安全场景应在 HTTPS 反向代理后使用。

## HTTP 边界

无需认证即可访问：

- `/`
- `/app.js`
- `/style.css`
- `GET /api/auth/status`
- `POST /api/auth/login`

页面和静态资源保持公开，以便渲染登录界面，但不包含 Session、文件、图片或密码数据。

密码启用时，下列所有资源均要求有效 Cookie：

- Session 快照和 SSE
- 发消息、取消任务与队列操作
- Session 释放、重连与同步
- 模型设置
- 上传后图片读取
- 工作区文件与代码预览

未登录请求返回 HTTP `401` 和统一的“需要密码登录”错误。密码关闭时，这些路由保持当前行为。

登录接口仍执行现有的局域网 IP、Host、Origin、JSON Content-Type 和 CSRF 校验。密码不进入 URL、访问日志或错误日志。

## 登录失败限制

服务端按来源 IP 在内存中记录最近 60 秒的失败时间：

- 60 秒内最多允许 5 次错误密码。
- 达到上限后，后续登录请求返回 HTTP `429`。
- 60 秒窗口自然过期后恢复尝试。
- 登录成功后清除该 IP 的失败记录。
- 桥接器重启会清空限制状态。

限制只作用于密码错误，不影响已认证请求，也不把失败状态持久化到磁盘。

## 网页交互

页面启动顺序改为：

1. 查询认证状态。
2. 无需密码或 Cookie 有效时，启动现有快照加载和 EventSource。
3. 未认证时显示居中的密码输入层，隐藏会话内容并保持消息输入不可用。
4. 登录成功后关闭登录层并启动正常数据流，无需刷新页面。
5. 登录失败显示通用错误；遇到 `429` 时提示稍后再试。
6. 运行期间任一 API 返回 `401` 时，停止 EventSource、回到登录层并等待重新登录。

同一浏览器配置文件中的多个标签页共享 Cookie，因此登录一次后都可以访问。不同浏览器或不同设备各自登录。

## 组件边界

- `lan_config.py`：解析并校验密码配置。
- `lan_access.py`：保持现有网络、Host、Origin 与 CSRF 校验，不承担密码会话状态。
- `lan_web.py`：维护认证 token、失败次数和路由认证边界。
- `web/index.html` 与 `web/style.css`：提供登录层结构和自适应样式。
- `web/app.js`：管理认证状态、登录请求以及认证后的数据流启动。
- `lan_main.py`：将配置密码传入 Web 应用，不记录密码。

## 错误处理

- 密码错误：`401`，统一错误信息。
- 缺失或无效 Cookie：`401`，提示需要登录。
- 尝试过多：`429`，提示稍后重试。
- 认证状态判断、Cookie 解析或其他未知服务异常：沿用现有服务器错误记录，不输出密码或 Cookie token。

## 测试

- 配置默认值为空、读取非空密码、保留空格以及拒绝非字符串。
- 空密码模式下现有路由和页面行为不变。
- 非空密码模式下，未认证的快照、SSE、图片、文件和写接口均返回 `401`。
- 错误密码返回 `401`，正确密码返回会话 Cookie。
- Cookie 带有 `HttpOnly`、`SameSite=Strict` 和 `Path=/`，且没有持久化期限。
- 有效 Cookie 可访问所有受保护路由；伪造或桥接器重启前的 token 被拒绝。
- 登录失败限流达到阈值后返回 `429`，窗口过期和成功登录可恢复。
- 网页不会在登录前创建 EventSource，登录后正常启动；运行期 `401` 会返回登录层。
- 运行完整 pytest、JavaScript 语法检查、Python 编译检查和现有 CI。
