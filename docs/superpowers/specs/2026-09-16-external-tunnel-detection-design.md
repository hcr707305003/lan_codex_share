# 外部 frpc / Cloudflare 状态检测

日期：2026-09-16。状态：书面规格已确认，当前分支实现和验证完成；未提交、打包或发布。

## 问题与目标

桌面当前仅识别外部 Share。frpc / Cloudflare 卡片只读取自己创建的 ServiceProcess，因此系统服务或终端启动的隧道会误显示“已停止”。启动 Share 的脚本实际不联动启动隧道，此语义保持不变。

补充后台只读检测，正确区分本客户端托管、外部运行、未发现实例及无法验证。防止用户在外部隧道运行时重复启动。进程运行不代表公网连接成功，不探测或宣称公网就绪。

## 方案选择

1. 推荐：读取实际进程信息，Windows 额外关联服务管理器中的 PID 和服务状态。覆盖终端、桌面及 Windows 服务启动方式，不接管外部生命周期。
2. 仅检测组件同名进程：改动少，但会混淆版本检查和其他隧道，不能据此宣称当前配置运行。
3. 使用服务托管或新启动记录统一接管：需要迁移既有服务，超出本次检测修正范围。

采用方案 1，沿用现有 psutil / Qt，不添加依赖，不修改组件安装和启动配置格式。

## 识别规则

- 枚举候选时结合可执行文件路径、程序名称和运行参数；识别标准与组件管理已支持的平台后缀名称。排除 frps、help/version 和 cloudflared 非隧道运行命令。
- frpc 的 `-c` / `--config`，Cloudflare 的 `--config` / `--token-file` 与当前桌面设置的规范化路径匹配时，标记为当前配置的外部实例。相对路径按目标进程工作目录解析；不可读取则不猜测。
- Windows 使用 psutil 的服务查询关联服务 PID，核对存活的实际组件进程；显示 Windows 服务来源。单凭服务名称或运行文件名不能证明当前配置归属。
- 外部 token / 默认配置等不能证明归属的实例，显示“检测到外部实例，配置未确认”，而不是声称当前隧道已连接。不得展示命令行、token、密码或读取 token 文件内容用于身份比较。
- 多个实例、权限不足、进程扫描期间退出或 PID 变化，显示多个实例或无法验证；不挑选任意实例、不接管。
- Windows 服务若处于启动/停止过渡期，显示过渡状态并阻止重复启动。macOS/Linux 只实现进程识别，不添加 systemd/launchd 管理。

## UI 与生命周期

- 保留现有卡片布局，每 3 秒异步刷新外部状态，主线程只渲染缓存。退出窗口后丢弃在途扫描结果。
- 当前配置明确匹配：显示“外部进程运行中”或“Windows 服务运行中”、PID，并注明“公网连接未验证”。其他配置或归属未知的候选明确标记，不误报当前配置正在运行。
- 所有外部运行、服务过渡、歧义或未知状态保守阻止桌面重复启动，按钮提示“外部运行 / 请检查”；用户仍可编辑配置，但不提供外部停止/强制关闭按钮。
- 已确认不存在外部候选时才恢复原有启动或组件安装入口；启动工作线程在调用 ServiceProcess.start 前再次进行只读检测，缩小状态过期导致重复启动的窗口，不承诺跨独立启动器的原子互斥。
- 自己托管的运行进程保持现有停止、日志和退出清理行为。自己的进程优先显示，不将外部实例伪装成自己的 Popen。
- 正常退出、Ctrl+C、配置保存和后台扫描均不停止、启动或重启外部隧道。外部实时日志不自动接入，不影响 Share 现有强制关闭功能。

## 验证与交付

- 单元测试模拟 frpc/Cloudflare、配置匹配与不匹配、token 保护、help/version 排除、多个实例、权限不足、PID 变化、Windows 服务状态以及非 Windows 分支。
- Qt 测试覆盖卡片和底栏一致、未知状态阻止启动、启动前重检、自己托管优先及窗口关闭不操作外部实例。
- 只读核对本机已运行的 Cloudflared 服务；所有启动/停止测试使用模拟对象或专用测试进程，不启停真实 Share、隧道或 PHP/Webman 服务。
