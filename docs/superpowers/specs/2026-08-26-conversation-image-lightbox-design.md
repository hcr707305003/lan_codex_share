# 会话图片灯箱预览设计

## 目标

为局域网共享 Codex 会话中的历史图片增加点击放大能力。用户无需离开当前会话即可在全屏深色遮罩中查看完整图片，并可通过鼠标、键盘或触屏安全关闭。

## 范围

- 支持已经进入会话历史的用户图片。
- 不改变待发送附件缩略图的交互，避免与其“移除附件”按钮冲突。
- 不增加滚轮缩放、双指缩放、拖动、旋转、下载或新标签页打开功能。
- 不修改图片上传、存储、接口权限或多 Session 数据结构。

## 交互设计

- 历史图片使用原生 `button` 包裹，使其可通过鼠标点击、触屏点击、Tab 和 Enter/Space 操作。
- 按钮使用图片名称生成可访问名称，例如“放大查看 screenshot.png”。
- 打开后显示覆盖整个视口的深色灯箱，图片在可用空间内等比缩放，使用 `object-fit: contain`，不裁剪、不拉伸。
- 用户可以通过右上角关闭按钮、`Esc` 或点击图片外的遮罩关闭。
- 点击图片本身不关闭，避免查看时误操作。
- 关闭后焦点恢复到触发灯箱的原图片按钮。
- 切换 Session 时若灯箱仍打开，先关闭灯箱再切换内容。

## 结构与层级

- 在主页面末尾增加独立灯箱节点，使用原生 `dialog` 元素提供模态语义与浏览器焦点约束。
- 灯箱包含关闭按钮、图片和屏幕阅读器可读标题。
- 灯箱层级高于右侧文件预览、移动端侧栏和拖拽遮罩，打开时不改变主页面 Grid 宽度。
- 页面使用现有关闭 SVG 图标，不引入新图片组件或第三方依赖。

## 状态与数据流

1. `renderGallery` 为每张历史图片创建按钮并绑定图片地址、名称。
2. 打开函数记录触发按钮，更新灯箱图片地址和替代文本，然后调用模态显示。
3. 关闭函数清空当前状态、关闭模态，并把焦点恢复到仍连接在 DOM 中的触发按钮。
4. 时间线重新渲染或 Session 切换导致触发按钮失效时，关闭后把焦点恢复到时间线。

灯箱只持有当前图片 URL 和临时焦点引用，不进入后端快照，也不影响实时消息同步。

## 可访问性

- 图片按钮有明确的可访问名称和可见焦点样式。
- 关闭按钮使用 `aria-label="关闭图片预览"`。
- 灯箱使用 `aria-labelledby` 关联当前图片名称。
- 原生模态负责把键盘焦点限制在灯箱内；关闭后恢复到合理位置。
- 图片加载失败时保留关闭能力，并显示可读错误状态。

## 响应式设计

- 桌面端图片最大宽高保留至少 `24px` 的视口边距，并为右上角关闭按钮保留空间。
- 手机端灯箱占满视口，触控关闭按钮至少 `44px`，图片仍完整适配，不受输入框和顶部栏影响。
- 使用 `100dvh` 适配移动浏览器动态地址栏。

## 验证

- 静态测试确认灯箱结构、模态语义、可访问名称、打开和关闭处理存在。
- JavaScript 语法检查与全量 Python 测试通过。
- 浏览器桌面验证：点击历史图片打开；图片完整显示；点击图片不关闭；点击遮罩、关闭按钮和 `Esc` 均可关闭；焦点恢复。
- 浏览器窄屏验证：灯箱覆盖完整视口，关闭按钮尺寸合格，图片不溢出。
- 同时打开右侧文件预览后再打开图片，灯箱仍位于最上层，关闭后文件预览状态不变。

## 错误处理

- 图片无法加载时显示“图片加载失败”，不无限显示空白区域。
- 触发图片在灯箱打开期间被会话刷新替换时，关闭后回退聚焦消息时间线。
- 重复打开同一图片只更新当前灯箱，不创建多个遮罩节点。
