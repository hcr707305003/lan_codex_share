# 文件预览布局恢复设计

## 背景

桌面端打开右侧文件预览时，应用由两列切换为三列。聊天主区域缩窄后，顶部标题和操作区的最小内容宽度会撑大网格，并产生横向溢出。关闭预览仅移除状态类，没有主动恢复焦点与横向滚动位置，因此顶部布局可能继续保持错位。

## 目标

- 文件预览打开时保留现有左右分栏体验。
- 顶部标题、Session、模型、连接状态和菜单始终位于可视区域。
- 关闭文件预览后立即恢复原布局，不残留横向偏移。
- 移动端继续使用全屏文件预览。
- 键盘用户关闭预览后回到原文件链接。

## 设计

### 布局约束

应用外壳固定在视口宽度内并禁止页面级横向溢出。主面板允许网格轨道收缩，其内部内容不得反向撑大应用外壳。文件预览仍使用现有的桌面三列网格和移动端全屏覆盖层。

顶部标题组占用剩余空间，标题容器显式设置可收缩宽度并使用省略显示。操作区保持可见；在预览态的较窄聊天区域内，逐步压缩 Session 与模型控件，而不是让整个页面横向扩张。

### 打开与关闭

打开预览前记录触发预览的文件链接。关闭时按以下顺序恢复：

1. 移除 `preview-open` 状态类。
2. 将应用外壳及页面横向滚动位置归零。
3. 把键盘焦点恢复到原文件链接；链接已不存在时回到聊天时间线。

关闭操作必须可重复调用，不产生异常或累积状态。

### 响应式行为

- 宽屏：侧栏、聊天区、文件预览三列并排。
- 中等宽度：聊天区顶部控件采用紧凑尺寸，标题优先省略。
- 820px 及以下：文件预览维持现有全屏覆盖层，不压缩聊天区。

## 验证

- 在约 1920px 宽桌面视口中反复打开和关闭文件预览，顶部不越界且关闭后恢复。
- 检查打开和关闭前后的页面横向滚动宽度，不能大于视口。
- 验证长会话标题、多个 Session、模型和连接状态同时存在时的顶部布局。
- 验证 820px 以下预览仍为全屏。
- 验证 Escape 和关闭按钮均恢复焦点。
- 运行现有 Python 测试和 JavaScript 语法检查。
