# 流水线发布文档与功能型 Release Notes 设计

## 目标

为维护者提供一份可直接照做的流水线发布文档，并确保每个 GitHub Release 清楚说明该版本新增、修复或改变了哪些用户可感知功能。

## 文档结构

- 仓库根目录新增 `PIPELINE_RELEASE.md`，说明流水线触发条件、首次配置、发布准备、版本号同步、版本说明编写、标签发布、产物校验、失败处理和回滚。
- `README.md` 增加维护者发布文档入口，不重复完整流程。
- `docs/releases/vX.Y.Z.md` 保存对应版本的 Release Notes，并作为 GitHub Release 正文的唯一人工维护来源。

## Release Notes 范围

版本说明只记录用户能感知的变化：

- 新增功能；
- 功能修复；
- 行为或兼容性变化；
- 使用新版本必须知道的升级提示。

纯文档调整、测试补充、内部重构、依赖例行维护和不影响产物行为的流水线优化不写入 Release Notes。若底层变更实际影响安装、启动、配置、兼容性或用户操作，则按其用户影响归入相应功能条目。

## 发布约束

发布标签继续采用 `vX.Y.Z`。标签构建开始前，流水线必须验证以下条件：

1. 程序版本与标签一致；
2. `docs/releases/vX.Y.Z.md` 存在；
3. 版本说明包含版本标题和至少一个非空的功能变化分类。

缺少有效版本说明时不创建 Release，避免发布只有提交列表、没有功能解释的版本。

## Release 生成

五个平台构建和冒烟测试保持不变。所有产物汇总后，发布任务使用对应的 `docs/releases/vX.Y.Z.md` 作为 Release 正文，并上传五个平台 ZIP 和 `SHA256SUMS.txt`。重复运行同一标签时覆盖产物并同步正文，保证流水线可重试。

## 当前版本补录

新增 `docs/releases/v0.1.1.md`，只描述该版本的功能新增、功能修复、行为变化和必要升级提示。完成后同步更新已经存在的 GitHub `v0.1.1` Release 正文。

## 验证

- 自动测试继续覆盖现有功能；
- 新增版本说明校验脚本测试，覆盖文件存在、版本匹配、有效功能条目和无效空模板；
- 对工作流和脚本执行静态检查；
- 使用 GitHub CLI 核验 `v0.1.1` Release 正文和六个发布资产。
