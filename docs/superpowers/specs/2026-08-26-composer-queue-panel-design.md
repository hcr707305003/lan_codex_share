# 发送框上方消息队列面板设计

## 目标

把尚未开始的排队消息从聊天时间线移动到发送框上方，以紧凑、可操作的队列面板集中展示。正式时间线只保留已经开始执行的用户消息和对应回复。

## 布局

- 队列面板位于处理状态条下方、图片预览和发送框上方。
- 队列为空时完全隐藏，不占据输入区空间。
- 面板标题显示“等待队列”和实时数量，右侧直接显示“清空”按钮。
- 队列列表设置最大高度，超过后在面板内部滚动，避免持续挤压聊天内容。

## 队列项

每条队列消息按 FIFO 顺序显示：

- 当前排队序号；
- 最多两行的文字摘要；
- 没有文字时显示图片消息说明；
- 图片数量、来源 IP 和发送时间；
- 单条“取消”按钮。

单条取消和清空操作继续只删除尚未开始的排队消息，不中断正在处理的任务。操作进行时按钮进入禁用和忙碌状态，完成后通过现有状态区域反馈结果。

## 实时行为

服务端数据结构和接口保持不变。所有页面继续从 Session 快照的 `pending` 和 `queue_size` 渲染同一个队列；任一页面发送、取消或清空后，其他页面在下一次实时刷新中同步变化。

排队消息不再渲染到聊天时间线。消息开始执行并进入真实 Session 后，按原有“一问一答”结构出现在时间线中，因此不会产生重复消息。

## 响应式与无障碍

- 桌面端保持完整摘要和元数据。
- 窄屏压缩间距和辅助信息，但保留文字摘要、序号和操作按钮。
- 队列数量通过单个原子 `role=status` 区域播报，避免每条刷新产生多个竞争播报。
- 取消和清空使用原生按钮，具有明确可访问名称、禁用状态和键盘操作能力。
- 动画遵循现有 `prefers-reduced-motion` 规则。

## 验证

- 静态页面测试确认队列面板、清空按钮和 API 绑定存在，旧时间线排队渲染被移除。
- 现有服务测试继续验证 FIFO、单条取消、批量清空和图片清理。
- 桌面端和 375px 移动端浏览器验证空队列、有队列、长消息、多条消息、单条取消和清空布局。
- 本次不修改版本号、不创建标签、不构建原生安装包。
