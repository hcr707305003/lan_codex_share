# 项目别名与公共 Markdown 公告

日期：2026-09-29
状态：用户已确认书面规格，已实施并验证。

## 目标与范围

为网页左侧“项目 → Session”提供项目资料，让访问者知道项目用途、相关网站和注意事项。同一项目下所有会话共用资料，访问 Share 的用户均可查看、编辑。沿用现有项目密码，不新增账号或角色。

本次只修改 lan_codex_share。资料不写入业务项目 README、AGENTS.md 或会话记录，不自动注入 AI 提示词。不改真实工作目录、Session 名称、访问权限或预览目录范围。不包含推送、发布、打包和运行服务重启。

## 已选方案

使用 Share 服务端独立资料文件，而不是业务项目内 Markdown 文件。优点是没有业务仓库改动，适合多人共享；代价是备份、迁移 Share 时需保留其 runtime 数据。

## 项目身份与数据

- 复用当前按规范化工作目录分组的项目身份，提取共用身份函数，避免长短路径等价目录出现两份资料。
- 别名只是展示名，不作为项目主键；不同目录即使别名相同也不合并。
- 无工作目录的“未分配项目”不提供编辑入口，避免无关会话共用资料。
- 每条记录包含 alias、notice_markdown、revision、updated_at。
- alias 去除首尾空白，最多 100 字符，不允许换行或控制字符；留空恢复默认目录名。
- notice_markdown 最多 64 KiB（UTF-8），允许为空以清除公告，保留 Markdown 换行。
- 配置文件所在目录下的 runtime/lan/project_profiles.json 保存版本化数据；该路径被 Git 忽略，不包含在发布包中。
- 项目暂时没有共享会话时保留资料，重新加入同一目录后恢复。目录迁移本次不提供自动迁移。

## 网页交互

1. 左侧项目标题显示别名，未设置则显示原目录名；旁边独立“项目说明”按钮，避免与折叠项目操作冲突。
2. 点击打开右侧资料面板，不切换 Session、不触发 AI 任务、不清空输入草稿。与文件预览共用侧栏空间，不并排挤出多个面板。
3. 查看模式显示项目别名、原始目录、Markdown 公告、更新时间和编辑按钮。没有公告时显示明确空态。
4. 编辑模式包含别名输入、Markdown 文本编辑和预览切换，以及保存、取消。初次创建不预填会自动保存的示例内容，只提供占位提示。
5. 别名同步应用到左侧项目分组、当前项目名称和“新任务”项目选择；会话标题保持原样，真实路径仍可查看。
6. 网站链接可点击打开新标签。使用现有安全 Markdown 渲染能力，禁用原始 HTML 和危险链接协议，不增加 Markdown 执行能力。资料中的文件链接不绕过现有预览鉴权。
7. 面板在窄屏适配可用宽高并独立滚动；输入、按钮和说明不重叠，有键盘焦点和关闭入口。
8. 关闭、切换项目资料或打开文件预览会丢弃未保存编辑时，先确认；取消退出继续保留草稿。正在保存时防止重复提交。

## 服务端与同步

- 独立 ProjectProfiles 存储组件负责验证、版本、线程锁和原子文件替换，Hub 负责将元数据合并到项目摘要。
- 新增项目资料读取与保存接口；使用服务端已知且有工作目录的共享项目 ID 定位，不接受用户指定存储路径，也不创建任意项目。
- 读取、保存均沿用 Share 认证和 Host 检查；写入沿用 Origin/CSRF 防护。无密码模式下访问者也可编辑，README 明示这一点。
- 项目摘要仅携带 alias、revision 和是否有公告，不反复传送全文；打开面板时读取公告。
- 保存提交基础 revision，版本冲突返回 409，保留本地编辑并提示重新加载，不静默覆盖他人更新。不增加自动合并。
- 成功落盘后广播现有同步通知，其他浏览器更新别名；打开的只读资料刷新，编辑中的资料不覆盖，仅提示远端已更新。
- 保存失败保留旧文件和编辑内容，不广播成功。资料文件损坏时原聊天仍可使用，资料功能明确报错并禁止覆盖损坏文件；缺失文件视为空资料。
- 不因资料接口读取而恢复、创建或运行 Codex 会话。

## 验证与交付

- 单元测试：项目身份一致性、字段限制、空值清除、原子保存失败、损坏文件、重启恢复、版本冲突和未知项目拒绝。
- HTTP 测试：认证、Origin/CSRF、资料读取保存、错误状态，不扩大文件权限。
- 前端测试：安全 Markdown、别名同步、编辑草稿保护、并发冲突处理。
- 用隔离模拟数据实测桌面与窄屏、两浏览器同步、文件预览与资料面板切换、刷新后的持久化；不使用真实会话或更改线上配置。
- README 补充入口、Markdown 用法、访问者编辑权限、runtime 备份说明和“不自动发送给 AI”的边界。
