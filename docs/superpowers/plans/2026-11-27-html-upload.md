# HTML 附件上传

目标：HTML/HTM 沿用现有文档附件流程，选择或拖入即可发送，保留原文件下载。

设计：将源码作为用户材料提供给 Codex，并使用现有纯文本预览。保留标签、脚本源码和相对链接，不执行脚本或请求外部资源，不新增 HTML 页面渲染。编码、文件大小、Session 授权和隔离提取限制沿用文本附件。HTML 不再受字符数拒收限制：100,000 字符内发送完整源码，超过后自动转为原文件输入，模型获得完整文件路径并要求先读取文件；不做源码节选，网页预览显示完整源码，下载保留全部字节。

实施：
- 扩展前后端扩展名白名单、文件选择器、支持格式提示与 README。
- HTML/HTM 使用现有文本解码，并明确提示显示源码。
- 验证真实上传、模型输入、预览、原文件下载、编码、限额和跨会话授权；前端验证无 MIME 的文件选择及文本预览不创建 HTML 元素。

后续范围：按用户要求补充常用前后端源码、配置、数据、日志、SVG、ZIP/TAR.GZ。文本统一采用全文或完整原文件输入，压缩包只读目录、不解压或执行。前后端格式策略同步更新，并验证原文件、预览、重启后关联与跨会话权限。

发布：按用户追加要求统一发布 v0.6.1，先完成测试和打包验证，再提交、推送并通过标签流水线发布；不重启用户服务。
