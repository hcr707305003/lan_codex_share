# v0.1.6

## 新增功能

- 新增 `public_origin` 配置，支持同机 Cloudflare Tunnel 提供指定 HTTPS 公网入口，原有局域网访问保持可用。可仅使用项目密码，无需 Cloudflare Access 登录；程序不自动安装或管理 Tunnel。
- 新增同域名、同端口动态反代：访问 `/proxy/localhost:端口/` 或 `/proxy/内网IP:端口/` 即可打开其他 HTTP 服务，不需要逐项登记服务或增加子域名。支持前端 `#/login` 等路由、查询参数和服务间跳转。
- 支持 HTTP 常见请求方法、普通表单、multipart/二进制/chunked 上传、下载、SSE 和 WebSocket 双向转发。代理入口沿用项目密码，目标服务的登录仍保留。
- 新增跨端口自动适配：前端与 API 分别运行在不同本机或内网端口时，常见 fetch/Request、XHR/Axios、WebSocket、EventSource 和资源链接可以自动经共享入口访问。

## 功能修复

- 修复已代理的其他服务地址被重复添加当前服务前缀，影响跨服务链接、图片及重定向的问题。
- 修复动态图片在地址改写前尝试直连访客本机，以及带正文 Request 改写后触发 Chromium HTTP/1.1 流式上传失败的问题；保留请求方法、表单内容及调用参数。
- 修复接口根据公网 HTTPS 协议头和内网 Host 生成二维码等资源地址后无法经反代访问的问题。限定改写 JSON 中指向当前响应后端同一主机和端口的完整 URL，保留查询参数，不改对象键、普通文字、业务数字或其他服务地址。
- 将共享 HTTP 服务连接等待队列由 Python 3.11 默认的 5 调整为 128，缓解 Vite 大量模块等突发请求下的连接重置及由此可能产生的白屏/502；不代表所有 Cloudflare 502 都已解决。

## 行为或兼容性变化

- 公网入口仅接受配置的精确 HTTPS 域名及来自本机回环的回源连接，不依赖访客可伪造的转发头放行；公网登录 Cookie 带 Secure、HttpOnly 和 SameSite=Strict。
- `password = ""` 仍完全免登录，并非只读。公网访问者可发送任务并访问可达内网服务；务必设置密码、限制共享范围，并只代理可信服务。同域名子路径不是安全沙箱，Codex 权限模式不约束目标服务本身的操作。
- 仅代理回环/RFC1918 地址的 HTTP 服务；禁止共享服务端口、App Server 端口、公网/元数据目标、任意域名及非 HTTP 协议。不提供任意 HTTPS-only 回源支持。
- 最多缓冲改写 2 MiB 未压缩 HTML/CSS/JSON；压缩、超限及部分响应不改写。带正文的跨地址 Request 在浏览器中缓冲后发送，不保留该调用方式的流式上传。上传上限 128 MiB；HTTP 超时 30 秒，WebSocket 单方向空闲超时 30 分钟。
- 严格 CSP、Worker、Cookie 脚本和特殊路由仍可能需要应用自身适配。重复 Ctrl+C 打断退出清理的问题不包含在本次修复中。

## 升级提示

- 保留真实 `lan_config.toml` 和 `runtime/`，替换程序后重启共享服务并刷新浏览器；本版本包含服务端变更，仅刷新页面不够。
- 仅局域网用户无需新增配置。公网用户设置 `public_origin` 和项目密码，并让同机 Tunnel 回源到共享 Web 端口，保留原始 Host。
- 无需修改或重启被代理的业务服务。新版启动后请分别验证共享首页、代理页面和接口资源；源服务本身不可用时仍会返回错误。
- 提供 Windows x64、Linux x64 / ARM64、macOS Intel / Apple Silicon 五个平台版本包及 SHA-256 校验文件，继续支持 Share、CLI 子命令和 `--config`。
